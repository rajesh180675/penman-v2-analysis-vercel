# UI Revamp Design Plan — Professional-Grade Financial Analysis Platform

**Date:** 2026-05-22
**Goal:** Transform the UI from "data dump with tabs" into a professional financial modelling screen that communicates insight, context, and narrative — not just numbers.

---

## Current State Assessment

### What Exists (Data Layer — Strong)
- 19 tabs across 6 groups: Input (5), Analysis (7), Valuation (2), Peers (1), Export (1), Advanced (3)
- Engine outputs: Penman-Nissim decomposition, 9 NBFC lenses, moat scoring, capital allocation scoring, distress detection, cyclical normalization, valuation command center, loss-maker anchors, regime model
- 93 component files, ~8,500 LOC in the 9 main views
- DashboardView (300 LOC) already has: KPI tiles, ValuationRangeGauge, InvestmentThesisCard, NarrativeCard, MoatPanel, SegmentBreakdown, QualitySignalPanel

### What's Wrong (Presentation Layer — Weak)
1. **No visual hierarchy** — everything is the same importance level. User sees 50+ numbers and doesn't know where to look first.
2. **No business context** — ratios shown without explaining what they mean, what's good/bad, why it matters for THIS company type.
3. **No storytelling** — data presented as isolated metrics, not as a connected narrative ("Revenue is growing but ROCE is declining because leverage increased").
4. **Tab overwhelm** — 19 tabs is Bloomberg-level complexity without Bloomberg-level visual scaffolding.
5. **Inconsistent density** — some tabs are wall-of-numbers (Ratios, Valuation), others are sparse (Dashboard, Statements).
6. **No progressive disclosure** — expert-level decompositions shown at the same level as headline numbers.
7. **Landing experience** — CompanyLibraryGrid → data entry form → suddenly 19 tabs. No guided journey.
8. **No print/export design** — screens designed for scrolling, not for generating a PDF equity report.

---

## Design Philosophy

**"Institutional equity research meets modern product design."**

Reference: Bloomberg Terminal (data density) × Stripe Dashboard (clarity) × Linear (navigation) × Koyfin (financial charting)

### Core Principles
1. **Verdict first, detail on demand** — every screen opens with a one-line conclusion, then supports it.
2. **Business language, not accounting language** — "This company earns 47% on every rupee of capital employed" not "ROCE = 0.47".
3. **Company-type-aware narration** — a bank screen talks about NIM and credit costs, not margins and turnover.
4. **Traffic-light confidence** — every output shows its data quality anchor (green = audited, amber = estimated, red = unreliable).
5. **Layered density** — L1 (headline verdict), L2 (supporting charts), L3 (detailed tables), accessible via expand/scroll.

## Phase 1: Design System Foundation

### 1.1 Typography & Color System
```
Font: Inter (body) + JetBrains Mono (numbers/data)
Scale: 11px (micro) / 12px (caption) / 14px (body) / 16px (subhead) / 20px (section) / 28px (page title)

Colors (dark mode primary):
  Background: slate-950 → slate-900 (cards) → slate-800 (elevated)
  Text: slate-100 (primary) / slate-400 (secondary) / slate-500 (muted)
  Accent: indigo-500 (primary) / emerald-500 (positive) / rose-500 (negative) / amber-500 (caution)
  Chart palette: [indigo-500, emerald-500, amber-500, rose-500, violet-500, cyan-500, orange-500, pink-500]

Light mode:
  Background: white → slate-50 (cards) → slate-100 (elevated)
  Text: slate-900 / slate-600 / slate-400
```

### 1.2 Card System
```
.card-base: rounded-xl border border-slate-200 dark:border-slate-800 bg-white dark:bg-slate-900 shadow-sm
.card-elevated: ... + shadow-md ring-1 ring-slate-100 dark:ring-slate-800
.card-verdict: ... + left-4 border-l-4 (green/amber/red based on verdict)
.card-metric: compact 100px height, number-first, caption below
```

### 1.3 Component Library (New Shared Atoms)
| Component | Purpose |
|-----------|---------|
| `<MetricCard>` | Single number + label + context sentence + optional sparkline |
| `<VerdictBanner>` | One-line conclusion with confidence badge (replaces InvestmentThesisCard) |
| `<InsightBlock>` | 2-3 sentence explanation of what the numbers mean, auto-generated |
| `<ExpandableSection>` | L1 header visible, L2/L3 detail on click |
| `<ConfidenceBadge>` | Green/Amber/Red dot + "High/Medium/Low confidence" text |
| `<TrendIndicator>` | ▲/▼/→ with color + "vs last year" or "5Y CAGR" |
| `<BenchmarkBar>` | Horizontal bar showing where value sits vs industry/sector band |
| `<ChartWithNarrative>` | Chart + auto-generated 1-line takeaway below |
| `<DataTable>` | Sortable, with heatmap coloring, CAGR column, conditional formatting |

## Phase 3: Business-Aware Narration Engine

### Auto-Generated Insight Sentences

Every section gets a computed narrative. Examples:

**Dashboard:**
> "ITC earns 47.6% on equity, placing it in the top decile of Indian industrials. Returns are driven by exceptional margins (33%) rather than capital efficiency. The company is a net-cash compounder — financial leverage actually drags ROCE by 0.4pp."

**Ratios (for a bank):**
> "HDFC Bank's NIM of 3.8% reflects strong pricing power on advances. Cost-to-income at 40% is best-in-class. GNPA at 1.2% (PCR 73%) indicates conservative provisioning. ROA of 1.9% × 8.2× leverage = 15.6% ROE."

**Valuation:**
> "Five frameworks converge between ₹520–675 (σ = ₹52). At ₹463, the stock trades at a 29% discount to midpoint. The primary risk to intrinsic value is a margin normalization scenario (EPV anchor at ₹548)."

### Implementation
```typescript
// src/engine/narrativeEngine.ts
export function generateDashboardNarrative(data: RecastPeriod[], config: EngineConfig, moat, capAlloc): string {
  const latest = data[data.length - 1];
  const roce = latest.ratios?.ROCE;
  const pm = latest.ratios?.PM;
  const ato = latest.ratios?.ATO;
  const flev = latest.ratios?.FLEV;
  
  const sentences: string[] = [];
  
  // ROCE context
  if (roce != null) {
    const roceDecile = roce > 0.30 ? "top decile" : roce > 0.20 ? "top quartile" : roce > 0.12 ? "above median" : "below median";
    sentences.push(`${config.ticker} earns ${(roce*100).toFixed(1)}% on equity, placing it in the ${roceDecile} of Indian ${config.company_type}s.`);
  }
  
  // Driver attribution
  if (pm != null && ato != null) {
    const driver = pm > 0.20 ? "exceptional margins" : ato > 2.0 ? "high capital efficiency" : "balanced margins and turnover";
    sentences.push(`Returns are driven by ${driver} (${(pm*100).toFixed(0)}% PM × ${ato.toFixed(1)}× ATO).`);
  }
  
  // Leverage context
  if (flev != null) {
    if (flev < 0) sentences.push(`The company is net-cash — financial leverage drags ROCE by ${Math.abs(flev * (latest.ratios?.SPREAD ?? 0) * 100).toFixed(1)}pp.`);
    else if (flev > 1) sentences.push(`Significant leverage (${flev.toFixed(1)}×) amplifies operating returns but adds risk.`);
  }
  
  return sentences.join(" ");
}
```

## Risks & Tradeoffs

1. **Scope** — This is a large surface area (9 major screens × 93 files). Suggest executing per-wave with user review between waves.
2. **Existing tests** — UI changes shouldn't break engine tests (800 pass). But snapshot/integration tests may need updating if they exist.
3. **Performance** — narrativeEngine adds computation per render; memoize with useMemo.
4. **Accessibility** — expandable sections need proper ARIA. Color-blind safe palette needed for traffic lights.
5. **Print/PDF** — @media print CSS needs separate attention (hide nav, expand all sections, use serif for readability).
