# Production platform activation runbook

This runbook activates the production valuation platform without inventing credentials, issuer evidence, calibration observations, or reviewer decisions. Repository validation proves software behavior; production activation additionally requires real provider configuration and independently sourced evidence.

## 1. Generate local-only secret material

Generate the secrets the repository can create safely. The command requires an explicit path, refuses to overwrite an existing file, applies restrictive file permissions where the operating system supports them, and never prints secret values.

```powershell
npm run platform:ops -- generate-secrets .env.platform.local
```

Fill the provider-owned blank values in that ignored file, then transfer all values into the deployment secret manager. Do not commit or attach the generated file.

Provider-owned inputs are:

- `PLATFORM_DATABASE_URL`
- `BLOB_READ_WRITE_TOKEN`
- `PLATFORM_SESSION_ISSUER`
- `PLATFORM_SESSION_AUDIENCE`
- `PLATFORM_OUTBOX_WEBHOOK_URL`
- `PLATFORM_HEALTH_ORGANIZATION_ID`
- `PLATFORM_HEALTH_WORKSPACE_ID`

The generator creates strong values for the backup HMAC key, outbox HMAC key, health token, and cron secret.

## 2. Run fail-closed configuration preflight

The report contains variable names and remediation guidance but never environment values.

```powershell
npm run platform:ops -- preflight runtime
npm run platform:ops -- preflight operations
npm run platform:preflight
```

`runtime` validates PostgreSQL, private Blob, HTTPS OIDC, and bounded connection settings. `operations` validates backup, cron, health, outbox, and capacity settings. `release` requires both profiles. Present-but-unsafe URLs, weak secrets, invalid base64 key material, placeholders, and unbounded numeric overrides fail closed.

## 3. Activate a staging workspace

Use real organization, workspace, and principal identifiers from the configured identity tenant.

```powershell
npm run platform:ops -- migrate
npm run platform:ops -- bootstrap-admin <organizationId> <workspaceId> <principalId>
npm run platform:ops -- probe <organizationId> <workspaceId>
npm run platform:ops -- backup <organizationId> <workspaceId>
npm run platform:ops -- restore-drill <organizationId> <workspaceId>
```

Bootstrap is deliberately single-use and fails if a membership already exists. Migrations fail on checksum divergence. The probe performs SQL and private-object-store round trips and remains blocked until migrations, backup freshness, and restore evidence satisfy policy.

## 4. Verify authenticated deployment behavior

1. Call `/api/platform/health` with `x-platform-health-token`; require HTTP 200 and `status: ready`.
2. Confirm the five-minute outbox, daily backup, and monthly restore-drill schedules execute successfully.
3. Run `npm run validate:release`.
4. Run `npm run test:e2e:tcs-audit` against staging.
5. Verify an OIDC user can access only workspaces authorized by signed organization membership.
6. Verify an unauthorized issuer, workspace, mutated advanced-model input, or unapproved evidence dossier fails closed.

## 5. Admit real analytical evidence

Production valuation readiness requires evidence that cannot be generated by application code:

- point-in-time calibration observations with real `forecastAsOf`, `realizedAt`, `availableAt`, and source references;
- reviewed issuer sidecars for each enabled sector model;
- real issuer goldens for promoted advanced models;
- two independent authenticated approvals for promotion and composition dossiers;
- approval evidence references that resolve to retained source material.

Test fixtures and AI-authored records must never be represented as independent approval or market evidence.

## 6. Release and rollback

Enable the platform by workspace feature flag after staging health, validation, and evidence admission pass. Preserve the prior application version, database backup, signing-key identifiers, and deployment configuration for rollback. Do not roll back database migrations by deleting migration records; deploy a reviewed forward migration.
